Baro Drift at Arm

You power up a copter, wait for a GPS lock, run your checks. The autopilot board warms up, and the barometer warms with it. Its height reading wanders, by about a metre in a few minutes on the vehicles measured. This page replays one of those benches, then shows what happens to that metre when you arm.

The reset, one sample wide

EKF height (m)EKF vertical speed, down (m/s), right axis

While the vehicle sits still, the filter follows the drifting barometer up to about 9.5 m. It also reports a phantom descent of 0.29 m/s, because it reads the drift rate as motion. At arm, height and that false speed both go to zero in one sample. Afterwards the vertical speed stays under 0.015 m/s, so the controller has no jump to chase.

When the reset is refused

Zeroing the height is only safe on the ground

The reset is valid only when the vehicle is on the ground, the height comes from the barometer or GPS, and nothing is moving. Arming does not guarantee any of that. A copter can be armed while you lift it, or re-armed after a mid-air disarm while it is still falling. Set up a case:

Bench data: real log12, BARO instance 0, 206 s, 41.8 to 61.8 °C, -1.17 m. SITL data: barodrift_arm.BIN from the PR analysis archive, XKF1 core 0. Master and PR outcomes follow the arming code on branch pr-baro-drift-minimum and the PR's SITL measurements.

The reset clears drift that built up before arming. It does not fix drift during flight; that needs a better temperature calibration or a second height reference.
